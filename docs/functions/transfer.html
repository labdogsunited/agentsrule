transfer

Transfers an amount of conserved substance between two stores with pro-rata shortfall arbitration.

void (effect) Context: Transfer rules, Genesis Phase: Move ⚖️ Conserved ⚡ GPU Contract

Synopsis

Synopsis — Emerge Language (.em) 
void transfer(substance s, store from, store to, amount[s] amount [, sink overflow]) @label;

Arguments

Argument Type Required Description
s substance Yes The declared conserved substance to move (e.g. carbon, light, body).
from store | source Yes Origin store: source (rock, sun), self (the current cell), or a neighbour cell (above, below, left, right).
to store | sink Yes Destination store: self, a neighbour cell, or a declared sink.
amount amount[s] Yes Quantity to transfer, strictly typed by substance s (e.g. 20mu, 5u). Amounts are unsigned saturating micro-units.
overflow sink No Optional fallback sink (e.g. void). If the destination lacks capacity, excess is vented to this sink instead of remaining at origin.

Returns

void (effect) — Produces a transfer effect submitted to the Move phase arbitration pool.

Details

`transfer` is the fundamental mechanism by which physical matter moves across the simulation. Because substances are strictly conserved, matter is never created or destroyed.

Two-Stage Pro-Rata Arbitration All transfers across all cells, rules, and creatures are arbitrated concurrently in the **Move phase**: 1. **Supply Contention:** If the total transfer requests drawn from a store exceed its available snapshot balance, each request receives a proportional fraction (floored). Leftover micro-units are distributed one by one to the largest fractional parts. 2. **Capacity Contention:** If the incoming amount exceeds the destination store's remaining headroom (`cap(s) - balance`), incoming transfers are scaled down pro-rata. 3. **Overflow:** If an `overflow` sink is provided, rejected headroom surplus is diverted into that sink. Without an overflow sink, surplus remains safely at the origin store.

Transfers between cells in world rules (`from: self, to: above`) do not accept an overflow argument.

Examples

Example — transfer 
// Inflow from source to cell with overflow sink
rule weather on cells {
    transfer(carbon, from: rock, to: self, amount: 20mu, overflow: void) @transfer_carbon;
    
    // Transfer from self to neighbour below
    when self.grain > 0u and below.grain < cap(grain) {
        transfer(grain, from: self, to: below, amount: 1u) @transfer_grain;
    }
}
